# Technical Debugging Codec

## 1. Anti-Compensation Rule
* **Заборонено "компенсацію" на дочірніх рівнях**: Жодних патчів, дублювання логіки або розгалужень (branching) у компонентах, щоб обійти баги бекенду.
* Уникай "one-file fixes". Якщо ти правиш лише один файл, обґрунтуй, чому інші рівні системи (API, Shared types, DB) не потребують змін.

## 2. Parent-First Inspection
* Якщо баг з'явився у дочірньому компоненті або сервісі — спочатку перевір батьківський рівень (Parent/Owner layer). Проблема часто в тому, які дані прокидаються зверху.

## 3. Atomic Alignment (Синхронізація шарів)
При зміні будь-якої механіки ти ЗОБОВ'ЯЗАНИЙ синхронізувати всі пов'язані шари:
* Контракти (Shared interfaces).
* Хендлери (Backend controllers).
* Запити та Кеш (React Query keys/hooks).
* Серіалізатори (DTOs).
* Стани завантаження та помилок (Loading/Error UI).

## 4. Systemic Fixes
* Віддавай перевагу системним змінам архітектури перед швидкими "латкам". 
* Якщо виправлення вимагає ре-архітектури (Re-architecture):
    1. Визнач Scope (обсяг).
    2. Оціни Risks (ризики).
    3. Перевір Compatibility (сумісність).
    4. Опиши Rollout order (порядок впровадження).

## 5. Frontend-Specific Flow
Для будь-якої помилки на фронті агент повинен проаналізувати повний ланцюжок:
`Route -> Layout -> Page -> Hooks -> API API -> Backend Service -> DB`.
