# Full-Stack Development Guidelines (NestJS + React Native Expo)

Цей документ визначає стандарти написання коду для монорепозиторію. Проєкт складається з бекенду (NestJS), фронтенду (React Native + Expo Router) та спільного пакета для типів. ШІ-асистенти ПОВИННІ суворо дотримуватися цих правил.

## 1. Архітектура Монорепозиторію (Shared Types - НАЙВИЩИЙ ПРІОРИТЕТ)
* **`packages/shared`**: Всі базові інтерфейси (напр., `IUser`), контракти запитів (`LoginRequest`, `RegisterRequest`) та відповідей (`AuthResponse`) **мають** створюватися тут.
* **Backend DTOs**: Бекенд DTO повинні імплементувати (implements) або розширювати спільні інтерфейси. 
  * *Приклад*: `export class RegisterDto implements Omit<IUser, 'id'> { ... }`
* **Frontend**: Фронтенд використовує спільні інтерфейси безпосередньо для типізації відповідей API (React Query) та стейту.
* **Заборона дублювання**: Ніколи не дублюй інтерфейси. Якщо тип потрібен і там, і там — винось його в `@athlo/shared`.

## 2. Backend Rules (NestJS)
* **Структура модуля**: Кожен ресурс має свій модуль, контролер, сервіс та DTO (згідно з CLI NestJS).
* **Валідація**: Суворо використовуй `class-validator` та `class-transformer` у DTO.
* **Контролери (Controllers)**: Лише обробка HTTP-запитів, роутинг та декоратори (`@Body()`, `@CurrentUser()`). Жодної бізнес-логіки.
* **Сервіси (Services)**: Вся бізнес-логіка та взаємодія з базою даних живе тут.
* **Безпека**: Всі ендпоінти мають бути захищені за замовчуванням (напр., глобальний `JwtAuthGuard`), а публічні ендпоінти позначаються декоратором `@Public()`.
* **Документація API**: Обов'язкове використання декораторів `@nestjs/swagger` (`@ApiTags()`, `@ApiResponse()`, `@ApiProperty()`) для автогенерації Swagger-документації.

## 3. Frontend Rules (React Native + Expo Router)
* **Структура**: Feature-based + Atomic Design.
  * `app/`: Тільки файли роутингу (Expo Router). Використовуй групи роутів `(auth)` та `(app)`.
  * `components/`: Перевикористовувані UI-компоненти.
  * `hooks/api/`: Кастомні хуки React Query для взаємодії з бекендом.
* **Data Fetching (React Query)**:
  * Всі запити (GET) та мутації (POST/PUT/DELETE) виносити в окремі хуки.
  * Використовувати об'єкт `queryKeys` для консистентності кешу.
  * Застосовувати Optimistic Updates для покращення UX (наприклад, при збереженні тренування).
* **Стилізація**: Уникай інлайнових стилів. Використовуй `StyleSheet.create` (або NativeWind/Tailwind, якщо налаштовано).

## 4. TypeScript та Clean Code
* **Суворий TS**: Використання `any` заборонено.
* **Принципи**: DRY, KISS. Розбивай великі функції на менші, тестовані одиниці.
* **Обробка помилок**: Завжди обробляй винятки (try/catch в сервісах, error state у React Query).
