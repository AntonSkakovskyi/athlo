### РОЗДІЛ 3. Проєктний розділ — 8–15 стор.

> [!tip] Наприклад:
> «Проєктування архітектури мобільного застосунку для планування тренувань та харчування»

- [ ] **3.1. Архітектура системи**
  - Обраний архітектурний підхід
  - Детальне обґрунтування вибору
  - Принцип окремості (Separation of Concerns) — явний поділ на логічні частини: UI, бізнес-логіка, шар даних/БД
  - Атрибути якості: масштабованість, безпека, доступність
  - Зазначити, які фреймворки використовуються для реалізації архітектурних рішень
  - Діаграма компонент (логічна архітектура) — для кожної компоненти описати призначення та перелічити основні відповідальності
- [ ] **3.2. Інфраструктурне представлення**
  - Діаграма розгортання (фізична архітектура) — для кожного вузла описати призначення та основні відповідальності
  - детальний опис обраних сервісів
- [ ] **3.3. Динамічна складова**
  - Діаграма діяльностей 
- [ ] **3.4. Проєктування бази даних**
  - Тип бізнес-середовища БД: OLTP (транзакційна обробка даних фітнес-застосунку)
  - середовище запуску(supabase), якщо це тут потрібно 
  - Обчислювальне середовище: клієнт-сервер або локальна БД на пристрої (обґрунтувати)
  - ER-діаграма (сутність-зв'язок) — вхідна інформаційна модель
  - Фізична модель БД — може бути перетворена на SQL/DDL-скрипт (скрипт подається в Додатку Г)
  - Проєктування об'єктів БД: таблиці (Users, Workouts, Exercises, MealPlans, FoodItems, Progress тощо), представлення (views), індекси; тригери та збережені процедури — за потреби
- [ ] **3.5. Проєктування інтерфейсу користувача**
  - Wireframe для основних екранів (Low-fidelity Wireframes) — тренування, логування їжі

## Вимоги до оформлення (шпаргалка)

| Параметр | Значення |
|----------|----------|
| Шрифт | Times New Roman, 14 кегль |
| Інтервал | 1.5, міжабзацні = 0 |
| Вирівнювання | По ширині |
| Абзацний відступ | 1.25 см |
| Поля | ліве ≥25мм, праве ≥10мм, верх/низ ≥20мм |
| Нумерація стор. | Вгорі справа, починаючи з 4-ї сторінки |
| Рисунки | Рис. X.Y — наскрізна в розділі, підпис під рисунком |
| Таблиці | Таблиця X.Y — праворуч, назва з нового рядка по центру |
| Код (основний текст) | Courier New, 10 кегль, не більше 1/3 сторінки |
| Код (додатки) | Courier New, 7–8 кегль, 2 колонки |
| Формули | Нумерація (X.Y) біля правого краю |
| Антиплагіат | ≥70% оригінальності = допустимий |
| Сторінка | Заповнена ≥90% |

> [!warning] Типові помилки з ДЕК
> - Відсутні висновки до кожного розділу
> - Рисунки без посилань у тексті
> - Скорочення без розшифровки або переліку
> - Одні рисунки на сторінці без тексту — зменшити і додати текст
> - Міжабзацні відступи ≠ 0
> - Порушення нумерації (пункт 1 після 2.2.3)
> - Назви розділів типу «Оглядовий розділ» замість конкретних назв
