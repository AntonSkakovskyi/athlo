### Слайд 2 — Актуальність
**На слайді:**
- Fitness-app market: $12.1B (2025) → $33.6B (2033), CAGR 13.4%
- WHO: 1B+ people overweight or obese
- Training and nutrition are one process — but apps cover only one side

**Доповідь:**
> The market of mobile fitness applications is growing steadily — from about twelve billion
> dollars in 2025 to a projected thirty-three billion by 2033. At the same time, training and
> nutrition are two parts of one process: the effect of training depends on the quality of the
> diet, and nutritional needs depend on the type of load. However, existing applications serve
> only one side — workout trackers do not record nutrition, and calorie counters barely reflect
> physical activity. This forces users to keep two separate apps with fragmented data, which
> makes an integrated solution relevant.

### Слайд 3 — Постановка задачі
**На слайді:**
- Goal: a cross-platform mobile app uniting workout logging and nutrition tracking in one environment
- Tasks: analyze domain & analogues · form requirements · design architecture & DB · implement · test

**Доповідь:**
> The goal of the work is to develop a cross-platform mobile application, called Athlo, that
> unites workout logging and nutrition tracking in a single environment. To achieve this goal,
> the following tasks were defined: to analyze the domain and existing analogues; to form
> functional and non-functional requirements; to design the system architecture and the
> database; to implement the application; and to test it against the requirements.

### Слайд 4 — Інструментальні засоби розробки
**На слайді:**
- Language: TypeScript — shared types & API contracts across client and server
- Client: React Native + Expo (iOS & Android, one codebase)
- Server: NestJS on Node.js — REST API
- Database: PostgreSQL via TypeORM

**Доповідь:**
> A single programming language, TypeScript, was chosen for both the client and the server.
> This lets data types and API contracts be shared between the two sides through a common
> package. The client is built with React Native and Expo, which produces native applications
> for iOS and Android from one codebase. The server is a REST API built with NestJS on
> Node.js. For data storage, the relational database PostgreSQL was chosen, accessed through
> the TypeORM library.

### Слайд 5 — Архітектура та розгортання
**Візуал:** діаграма компонентів (`diagrams/component-diagram.drawio`) + вставка діаграми розгортання (`diagrams/deployment_diagram.drawio`)
**На слайді:**
- Client–server, 3 logical layers: presentation / application / data
- Server: 3 tiers (controllers → services → repositories), 4 domain modules
- Stateless REST over HTTPS, JWT auth
- Deploy: Expo EAS (client) · Render (server) · Supabase (PostgreSQL)

**Доповідь:**
> The system uses a client-server architecture with three logical layers: presentation,
> application, and data. The mobile client only displays data and handles user interaction; all
> business logic lives on the server. The server itself follows a three-tier scheme —
> controllers, services, and repositories — and is split into four independent domain modules:
> users, the exercise catalogue, workouts, and nutrition. Communication is stateless: each
> request carries a JWT token over HTTPS. For deployment, the client is built through Expo
> Application Services, the server runs on Render, and the database is hosted on the managed
> Supabase platform.
